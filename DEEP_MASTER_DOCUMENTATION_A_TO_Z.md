## 4. Mathematical & Theoretical Foundations

### 4.1 Sensor Transfer Function: MCP9701 Linear Active Thermistor
The onboard temperature sensor on channel `AN0` (`RA0`) of the PIC18F Trainer board is a Microchip MCP9701-E/TO linear active thermistor. Unlike the LM35 (which has a 10 mV/°C slope and 0 mV offset), the MCP9701 is engineered for sub-zero measurement with a 400 mV offset at 0°C and a temperature coefficient of 19.5 mV/°C:

$$V_{\text{out}} = V_{0^\circ\text{C}} + T_C \cdot T_A = 400.0\text{ mV} + 19.5\text{ mV}/^\circ\text{C} \cdot T_A$$

Solving for ambient temperature $T_A$:

$$T_A = \frac{V_{\text{mV}} - 400.0}{19.5}$$

To suppress high-frequency thermal and switching noise from the board's power supply, the driver calculates a rolling 16-sample moving average:

$$\bar{V}_{\text{mV}} = \frac{1}{16} \sum_{i=1}^{16} V_{\text{ADC}}^{(i)}$$

### 4.2 Online EWC++ (Elastic Weight Consolidation) Continual Learning
When fine-tuning local neural weights across successive nightly sleep cycles, catastrophic forgetting of previously acquired skills (such as SQL guardrails or PIC18F pinouts) is prevented using Online EWC++. The diagonal Fisher Information Matrix $F$ measures parameter importance. Across training episodes, $F$ is updated using exponential decay:

$$F_{\text{running}}^{(t)} = \gamma F_{\text{running}}^{(t-1)} + (1 - \gamma) F_{\text{task}}^{(t)}$$

where $\gamma = 0.90$ is the momentum retention factor. During nightly fine-tuning, the total loss function regularizes weight drift from the historical reference parameters $\theta^*$:

$$\mathcal{L}_{\text{total}}(\theta) = \mathcal{L}_{\text{task}}(\theta) + \sum_{i} \frac{\lambda}{2} F_{\text{running}, i} \left(\theta_i - \theta_i^*\right)^2$$

### 4.3 Multi-Objective Preference Optimization Losses

#### 1. Odds Ratio Preference Optimization (ORPO)
Combines standard Supervised Fine-Tuning (SFT) cross-entropy loss with an odds-ratio penalty on dispreferred completions without requiring a separate frozen reference model:

$$\mathcal{L}_{\text{ORPO}} = \mathcal{L}_{\text{SFT}} + \lambda \mathcal{L}_{\text{OR}}$$

where the odds ratio $\text{OR}(y_w, y_l)$ between winning completion $y_w$ and losing completion $y_l$ is given by:

$$\text{odds}(y|x) = \frac{P_\theta(y|x)}{1 - P_\theta(y|x)}, \quad \mathcal{L}_{\text{OR}} = -\log \sigma \left( \log \frac{\text{odds}(y_w|x)}{\text{odds}(y_l|x)} \right)$$

#### 2. Simple Preference Optimization (SimPO)
Eliminates reference model memory overhead by using the length-normalized sequence log-probability with a target reward margin $\gamma = 0.5$:

$$\mathcal{L}_{\text{SimPO}}(\pi_\theta) = -\log \sigma \left( \frac{\beta}{|y_w|} \log \pi_\theta(y_w|x) - \frac{\beta}{|y_l|} \log \pi_\theta(y_l|x) - \gamma \right)$$

#### 3. Direct Preference Optimization (DPO)
Implicitly optimizes the Bradley-Terry preference model relative to frozen reference policy $\pi_{\text{ref}}$:

$$\mathcal{L}_{\text{DPO}}(\pi_\theta; \pi_{\text{ref}}) = -\mathbb{E}_{(x, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right) \right]$$

### 4.4 LoRA Adapter Matrix Merging
To fuse trained low-rank matrices $A \in \mathbb{R}^{r \times d_{\text{in}}}$ and $B \in \mathbb{R}^{d_{\text{out}} \times r}$ into base weight matrix $W_0$:

$$W_{\text{merged}} = W_0 + \Delta W = W_0 + \frac{\alpha}{r} (B \cdot A)$$

where $r$ is the LoRA rank (typically 16) and $\alpha$ is the scaling factor (typically 32).

### 4.5 Differential Shadow Output Divergence
When evaluating a mutated tool variant $V_{N+1}$ against production baseline $V_N$ over $K$ test payloads:

$$\Delta_{\text{divergence}} = \frac{1}{K} \sum_{k=1}^K \mathbf{1}\left(O_{\text{shadow}}^{(k)} \neq O_{\text{prod}}^{(k)}\right)$$

A candidate mutation is eligible for auto-promotion only when $\Delta_{\text{divergence}} = 0.0$ and latency speedup satisfies:

$$\text{Speedup} = \frac{\bar{t}_{\text{prod}} - \bar{t}_{\text{shadow}}}{\bar{t}_{\text{prod}}} > 0.05$$

## 5. Physical Hardware & Embedded MCU Toolchain (PIC18F85K22)

### 5.1 Physical Hardware Profile
- **Trainer Board**: Microchip PIC18F Trainer 2 Rev 1.24
- **Target MCU**: Microchip PIC18F85K22 (80-pin TQFP, 64 KB Flash, 3.8 KB SRAM, 1024 B EEPROM, 12-bit ADC).
- **Oscillator**: 4.9152 MHz external crystal (`#define _XTAL_FREQ 4915200`, `#pragma config FOSC = HS2`).
- **ICSP Debugger/Programmer**: Microchip PICkit 3 (Serial Number `BUR181916585`).

### 5.2 Mandatory Hardware Defect Workaround: LCD Line 1 Broken
> **CRITICAL DIRECTIVE**: Line 1 (address range `0x80..0x8F`) of the 16x2 HD44780-compatible LCD on this trainer board is physically defective and unreadable.
> **All primary UI text, sensor metrics, and alarms MUST be rendered solely on Line 2 (`LCD_Set_Cursor(2, 1)`, addresses `0xC0..0xCF`, max 16 characters).**

### 5.3 Board Pinout & Bus Mapping Table

| Board Component | Microcontroller Pins | Port Registers | Configuration / Directives |
| :--- | :--- | :--- | :--- |
| **16x2 LCD Data Bus** | `RH0` to `RH7` (8-Bit Mode) | `PORTH`, `LATH`, `TRISH` | `TRISH = 0x00;` (**NEVER route LCD data to PORTD**). |
| **LCD Control Lines** | `RE0` (RS), `RE1` (EN) | `PORTE`, `LATE`, `TRISE` | `LATEbits.LATE0 = rs; LATEbits.LATE1 = en;` |
| **LCD Backlight** | `RA4` | `PORTA`, `LATA`, `TRISA` | `TRISAbits.TRISA4 = 0; LATAbits.LATA4 = 0;` (Active Low turns backlight ON). RA4 is strictly reserved for backlight. |
| **Discrete Red LED Bar** | `RD0` to `RD7` (8 LEDs) | `PORTD`, `LATD`, `TRISD` | `TRISD = 0x00; LATD = bitmask;` |
| **Analog Thermistor** | `RA0` (Channel `AN0`) | `PORTA`, `ANCON0` | `ANCON0bits.ANSEL0 = 1;` MCP9701 linear math required. |
| **Piezo Buzzer** | `RF` / `RA5` / `RC3` | `PORTF`, `PORTA`, `PORTC` | Driven via PWM or timer toggle (RA4 is never used for buzzer). |
| **4x4 Matrix Keypad** | Rows `RJ[2:0]`, Cols `RC[2:0]` | `PORTJ`, `PORTC` | `#pragma config SOSCSEL = DIG` required to free `RC0`/`RC1` from secondary oscillator. |

### 5.4 PICkit 3 CLI Flashing Protocol
Programming and hex deployment can be executed headless via Microchip IPE command line:

```powershell

ipecmd.exe -P18F85K22 -TPPK3 -TSBUR181916585 -M -F"firmware/build/production.hex" -OL
```

## 8. Tri-Tier Cognitive Memory & Knowledge Graph Architecture

```
User Input ───► L1: Working Context (RAM Ring Buffer, last 20 turns)
                      │
                      ▼ (Background Async Flush)
                 L2: Ephemeral Cache (SQLite, session context & latency counters)
                      │
                      ▼ (Periodic Batch Consolidation)
                 L3: Sovereign Vector Store (PostgreSQL 16 + pgvector, 1536-dim)
                      │
                      ▼ (Entity & Relation Extraction)
                 Dynamic Property Knowledge Graph (Nodes, Edges, Properties)
```

### 8.1 Memory Tier Specifications
- **L1 (Working Context)**: In-memory sliding window holding active conversation turns, system prompts, and immediate tool results.
- **L2 (Ephemeral SQLite)**: High-speed local cache (`deep_cache.db`) indexing search tokens, temporary tool execution results, and circuit breaker metrics.
- **L3 (pgvector Sovereign Store)**: PostgreSQL database (`deep_db`) storing semantic memory across episodes. Text embeddings are projected into 1536-dimensional space and indexed via HNSW for sub-10ms nearest-neighbor retrieval:
  ```sql
  SELECT id, content, 1 - (embedding <=> $1) AS similarity 
  FROM memory_embeddings 
  WHERE 1 - (embedding <=> $1) > 0.75 
  ORDER BY similarity DESC LIMIT 5;
  ```
- **Dynamic Property Knowledge Graph**: Stores typed entities (`(User)-[:OWNS]->(Project)`, `(Task)-[:DEPENDS_ON]->(Tool)`) allowing graph traversals to provide structural context to the LLM.

## 9. Enterprise Zero-Trust Defense, AST Shield & Resilience

### 9.1 Zero-Trust Defense Layers
1. **Pre-Flight Secret Sanitization (`sanitize_secrets.py`)**: Automatically regex-scrubs API keys, private tokens, passwords, and PII from all logs, terminal outputs, and TTS voice speech.
2. **AST-Enforced SQL Guardrails (`enterprise_ai_guardrails.py`)**: Parses every LLM-generated SQL query into Python AST nodes. Mutating statements (`DROP`, `DELETE`, `TRUNCATE`, `ALTER`, `UPDATE`, `INSERT`) raise immediate `SECURITY_VIOLATION`. All `SELECT` queries without explicit limits are automatically rewritten to include `LIMIT 100`.
3. **Dynamic Tool AST Security Shield (`ASTSecurityShield`)**: Disallows dangerous modules (`winreg`, `ctypes`, `msvcrt`, `subprocess`, `socket`, `pty`) and builtins (`eval`, `exec`, `__import__`). Prohibits introspection escapes (`__subclasses__`, `__bases__`, `__globals__`).
4. **Sandboxed Subprocess Environment (`SandboxedEnvironment`)**: Executes unit tests in sanitized environments where credential variables (`TOKEN`, `KEY`, `PASS`, `SECRET`) are purged from `os.environ`.
5. **Stateful Hystrix Circuit Breakers (`hystrix_circuit_breaker.py`)**: Protects external devices (smart home, serial ports, cameras) by transitioning from `CLOSED` to `OPEN` after 3 consecutive failures, cooling down for 30s before attempting `HALF-OPEN` recovery.

### 9.2 Level 5 Autonomous Self-Healing Sentinel & Immune Governance (`autonomous_self_healing_engine.py`)
The workstation implements a comprehensive, 6-layer self-healing and immune subsystem:
- **6-Layer Diagnostic Matrix**:
  1. *Layer 1 (Process & Memory)*: Cyclic object garbage collection, cache purge when RAM > 80%.
  2. *Layer 2 (Storage & Databases)*: SQLite integrity verification, pgvector pool readiness probes.
  3. *Layer 3 (Circuit Breakers)*: Non-blocking canary probes; automatic reset of recovered circuits to `CLOSED`.
  4. *Layer 4 (Hardware Mutexes)*: Deterministic OpenCV camera handle and audio stream release; LCD Line 2 defect guard.
  5. *Layer 5 (Network & Sockets)*: Identification and dynamic mitigation of socket conflicts (e.g. port 2222/33060).
  6. *Layer 6 (Dynamic Tool Immune System)*: Continuous failure triage; automatic quarantine of tools with >= 3 crashes.
- **Multi-Candidate Patch Tournament (`HealingPatchTournament`)**:
  When a dynamic tool throws runtime exceptions, 3 candidate strategies compete:
  - *Candidate A (AST Mutation)*: Injects defensive guards for ZeroDivisionError, KeyError, TypeError, AttributeError, IndexError, and ValueError.
  - *Candidate B (LLM Reflexion)*: Prompt-engineered localized repair using local Ollama model.
  - *Candidate C (Snapshot Rollback)*: Restores the highest-scoring verified historical snapshot.
  Candidates are evaluated in the isolated sandbox; the candidate with the highest fitness is crowned and hot-swapped into production with a newly committed regression test.

| **`ConnectionRefusedError: [WinError 10061]`** | Flask daemon is not running on port 5000. | Start server via `python app.py` or inspect daemon background task. |

| **`yt-dlp download timeout`** | Network delay during missing song download. | Download runs asynchronously in background; UI does not hang. Track will auto-play upon completion. |
| **`Ollama connection refused on port 11434`** | Local Ollama service is stopped. | Run `ollama serve` in a separate terminal. |
